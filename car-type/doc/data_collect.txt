針對你目前的「綠色城市評估」專案，為了將原始複雜的車輛數據轉化為具備洞察力的儀表板，以下是為你總整的**資料清洗與標準化流程**。

這套流程能幫助你將車籍資料與手頭上 1,018 筆 PM2.5 實時數據[cite: 1] 進行有效的交叉比對。

---

### 第一階段：能源類型簡化 (Energy Mapping)
原始 13 類燃料定義過於細碎，應統一清洗為「三大指標」，以提升儀表板的可讀性：

*   **純油車 (ICE)：** 包含 (1) 汽油、(2) 柴油、(4) 液化石油氣、(5) 汽油/LPG。
*   **純電車 (BEV)：** 僅包含 (3) 電能。這是綠色城市最核心的增長指標。
*   **油電混合 (Hybrid)：** 包含 (6) 至 (13) 的所有分類。
    *   *註：雖然 (13) 汽油(電能) 能量來源是油，但在城市統計中通常歸類為 Hybrid 以簡化前端顯示。*

### 第二階段：車輛類別篩選 (Vehicle Filtering)
根據對空氣品質[cite: 1] 的影響程度，建議保留以下分組：

1.  **民用綠能組（小客車、機車）：** 用於評估市民生活轉型的程度，適合與住宅區、景區（如北投、鶯歌[cite: 1]）的空品比對。
2.  **商用/工業組（大客車、大貨車、小貨車）：** 這是 PM2.5 的主要移動污染源，適合與資料中標註為「工業區」或「營建工地」[cite: 1] 的測站進行交叉分析。
3.  **捨棄項目：** 「特種車」與「總計」建議隱藏，避免干擾主要趨勢線。

### 第三階段：時間與空間對齊 (Data Integration)

*   **時間週期：** 
    *   車輛登記數建議以 **「月」** 為單位計算趨勢折線圖。
    *   這能讓你觀察長期的「油轉電」比例是否與空品[cite: 1] 的 `aqi_level` 分布有負相關。
*   **空間聚合 (Spatial Join)：**
    *   利用你現有的 `coordinates`[cite: 1]，請後端將測站點位歸納至各個 **「行政區 (Township)」**。
    *   處理 `township` 欄位為 `null`[cite: 1] 的資料，建議透過座標反查（Reverse Geocoding）補齊，確保每一筆 PM2.5 數據都能對應到該區的車輛統計。

---

### 第四階段：技術實作邏輯（給後端夥伴｜靜態圖表、無地點維度）

**車輛類型統計圖**以**靜態圖表**呈現即可：**不需要** `township`、座標、或與 PM2.5 測站／GeoJSON 做 spatial join。後端只需依「時間（建議到月）＋縣市範圍（臺北市／新北市／雙北合計）＋車種／燃料三類」聚合後輸出 JSON；若日後要做空品交叉分析，另開獨立 API 與資料集即可。

你可以直接將以下邏輯與 **三種圖表的 JSON 合約範例** 提供給後端夥伴。

#### 1. 燃料分類清洗（與第一階段一致）

以原始 13 類燃料的**編號**對應時：

```python
def categorize_fuel(raw_fuel_id: int) -> str:
    if raw_fuel_id in (1, 2, 4, 5):
        return "ICE"      # 汽油、柴油、液化石油氣、汽油/LPG
    if raw_fuel_id == 3:
        return "BEV"      # 電能
    return "Hybrid"       # (6)～(13) 其餘混合／雙動力等
```

若以**欄位名稱**（例：來自公開統計 CSV 表頭）對應時，可等同映射：`汽油、柴油、液化石油氣、汽油/LPG → ICE`；`電能 → BEV`；`汽油/電能、柴油/電能、電能/汽油、電能/柴油、電能(增程)、汽油(油電)、柴油(油電)、汽油(電能) → Hybrid`。

#### 2. 三種前端圖表建議的 JSON 輸出格式

以下 **`meta` 僅描述「時間＋縣市範圍＋可選車種分組」**，不含任何地圖或測站欄位。數值以**新領牌輛數**為例；`ratio` 為 0～1 小數（前端可自行轉成百分比字串）。

**(A) Bar chart — 依「車種」比較數量（適合單一時間切片＋單一縣市範圍）**

```json
{
  "chart": "bar_vehicle_by_type",
  "meta": {
    "period_label": "114年 6月",
    "period_sort": "114-06",
    "scope": "臺北市"
  },
  "categories": ["小客車", "機車", "大客車", "大貨車", "小貨車"],
  "series": [
    { "name": "新領牌數", "values": [5230, 4618, 11, 32, 175] }
  ]
}
```

**(B) Donut chart — 單一時間切片下的**燃料結構**（ICE / BEV / Hybrid；可再細分民用／商用組）**

```json
{
  "chart": "donut_fuel_mix",
  "meta": {
    "period_label": "114年",
    "period_sort": "114-00",
    "scope": "新北市",
    "vehicle_group": "civilian"
  },
  "segments": [
    { "key": "ICE", "label": "純油", "count": 120400, "ratio": 0.78 },
    { "key": "BEV", "label": "純電", "count": 8500, "ratio": 0.055 },
    { "key": "Hybrid", "label": "油電／混合", "count": 25200, "ratio": 0.165 }
  ]
}
```

說明：`vehicle_group` 可為 `civilian`（小客車、機車）、`commercial`（大客車、大貨車、小貨車），或省略表示該 `scope` 下**保留車種**的合計。

**(C) Timeline stack chart — 以「月」為橫軸，堆疊 ICE／BEV／Hybrid（絕對數或 100% 堆疊）**

```json
{
  "chart": "timeline_fuel_stack",
  "meta": {
    "scope": "臺北市",
    "vehicle_type": "小客車",
    "unit": "輛",
    "stack_mode": "absolute"
  },
  "x": ["113-03", "113-04", "113-05"],
  "x_labels": ["113年3月", "113年4月", "113年5月"],
  "series": [
    { "key": "ICE", "label": "純油", "values": [3256, 3198, 3000] },
    { "key": "BEV", "label": "純電", "values": [834, 821, 882] },
    { "key": "Hybrid", "label": "油電／混合", "values": [652, 584, 701] }
  ]
}
```

說明：`stack_mode` 建議 `absolute`（輛數堆疊）或 `percent`（每月三類加總為 100% 的堆疊）；若為 `percent`，後端可回傳每個 series 在該月的比例陣列（0～1 或 0～100 與前端約定即可）。

#### 3. 後端聚合小抄（與第二階段一致）

*   **保留車種：** 大客車、大貨車、小客車、小貨車、機車。  
*   **排除：** 表冊最上層「全體總計」、與細項重複的「汽車」匯總列、特種車。  
*   **比率：** `bev_ratio = BEV / (ICE + BEV + Hybrid)`，同理可算 `ice_ratio`、`hybrid_ratio`；與 PM2.5／AQI **無需**在同一支 API 內計算。

### 💡 黑客松搶分重點建議

*   **異常值處理：** 你的資料中包含 `weight` 極高或測站標註為「營建工地」[cite: 1] 的點位。在清洗車輛資料時，應排除工地機具，專注於道路車輛的對比。
*   **視覺化回饋：** 車輛統計若僅做**靜態圖表**，環狀圖可直接使用第四階段的 `donut_fuel_mix`（依選定之縣市／月份），無需鄉鎮或測站欄位。若專案另做空品地圖聯動，再於選取區域時載入對應切片資料即可。
