### 1. 處理資料總量（Pagination 挑戰）
你在測試中看到的 `@iot.count` 是 **10,983** 筆。
*   **問題：** 預設情況下，API 一次只會回傳 100 到 1000 筆資料。
*   **解決方案：** 你不能只打一次 Request。你需要在後端寫一個 `while` 迴圈，檢查回傳資料中是否有 `@iot.nextLink`。如果有，就繼續抓下一頁，直到把所有雙北的點位抓完為止。

### 2. 精確的縣市篩選（City Filtering）
你的範例資料是「桃園市」，但比賽要求的是雙北。
*   **實作建議：** 在你整理 GeoJSON 的迴圈中，一定要檢查 `properties.city` 是否為 `臺北市` 或 `新北市`。
*   **小提醒：** 官方資料有時會混用「台北市」與「臺北市」，建議用 `if "台北" in city or "臺北" in city` 來做模糊匹配會比較保險。

### 3. Heatmap 的權重映射（Weight Mapping）
你將 `result` (9.24) 放入 `properties.weight` 是正確的做法。
*   **視覺化建議：** PM2.5 的數值範圍落差很大（普通時 10 左右，紫爆時可能破百）。在 Mapbox 設定 `heatmap-weight` 時，建議使用插值法：
    ```javascript
    "heatmap-weight": [
      "interpolate", ["linear"], ["get", "weight"],
      0, 0,    // 數值 0 時權重為 0
      35, 0.5, // 數值 35 (黃燈) 權重中等
      75, 1    // 數值 75 (紅燈以上) 權重最大
    ]
    ```

### 4. 針對「點」圖層的彈出視窗（Popup）
既然你的 GeoJSON 已經納入了 `stationID` 和 `phenomenonTime`，這對實作**互動儀表板**非常有幫助。
*   **應用場景：** 當使用者在地圖上點擊一個圓點時，你可以直接從 `properties` 抓出 `station` 名稱與「最後更新時間」，這能顯著提升「作品技術 (30%)」中關於數據整合的評分。

### 5. 時間格式處理
範例中的 `phenomenonTime` 是 `2026-05-02T07:20:36Z`（UTC 時間）。
*   **實作細節：** 顯示給雙北市民看時，記得在前端轉成在地時區（+8），否則評審可能會覺得你的數據延遲了 8 小時。
