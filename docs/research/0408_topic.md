# 五個雙北市政府迫切需要的 AI 題目

## 1. 雙北高齡長照與跨區醫療量能錯配

這是最穩的題目之一。原因很簡單：臺北高齡化明確上升，臺北市老化指數與扶養比資料持續更新；新北也長期面對各行政區長照需求與照顧比率差異很大的問題。這種題目天然符合「雙北生活圈」與「跨區資源調度」。([臺北市資料大平臺][2])

情境 A
白天醫療與長照需求集中在某些醫療核心區，但實際長者居住分布在外圍區，導致跨區就醫與照服派工失衡。

情境 B
某些行政區高齡人口成長快，但社區據點、日照、居服、接送資源成長慢，承辦單位很難快速判斷優先補點位置。

AI 缺口
不是缺聊天機器人，而是缺一個能把人口結構、照護量能、交通可達性、跨區流動與歷史趨勢壓縮成「哪裡先補、補什麼、為什麼」的決策摘要器。

### 需求 prompt 1

```md
# 任務名稱
雙北高齡長照與跨區醫療資源錯配儀表板研究

# 背景
雙北為單一生活圈，但高齡人口、長照需求、醫療量能、交通可達性與實際跨區就醫行為並不一致。我要先做一份可供黑客松快速落地的需求研究與 MVP 規格，主軸是找出「需求高但量能不足」與「跨區依賴過高」的行政區或服務類型。

# 目標
產出一份可直接轉成 GitHub issue / spec / demo script 的文件，內容需包含：
1. 問題定義
2. 雙北共融價值
3. 可用開放資料來源
4. 資料清理與欄位對映方案
5. 儀表板圖表設計
6. AI 功能邊界
7. MVP 範圍與 PR 可行模組
8. 評審視角風險與答辯重點

# 工作編排
- Gemini CLI：搜尋雙北官方開放資料、衛生/社福/人口/交通資料、官方政策文件、現有儀表板可重用元件
- Codex CLI Worker 1：撰寫需求文件初稿，格式要像黑客松提案 spec
- Codex CLI Worker 2：檢驗資料來源真實性、欄位可對接性、文件前後一致性，補上缺漏
- Claude Sonnet 4.6：依據政府評審方法論，嚴格審查應用價值、技術可落地性、AI 是否只是噱頭、是否具備賽後 PR 條件，並重寫成決選可用版本

# 輸出格式
1. 一頁式摘要
2. 問題樹
3. 資料源清單
4. 欄位 mapping 表
5. 圖表清單與互動邏輯
6. AI 功能設計
7. 風險與限制
8. Demo 口頭講稿

# 限制
- 不要做個人醫療預測
- 不要使用不可解釋黑箱作為核心
- AI 只能做摘要、比較、異常原因候選、決策說明
- 所有圖表都必須可在沒有 AI 時獨立成立
```

## 2. 雙北高溫熱島與脆弱族群保護

這題很強，因為臺北官方氣候調適文件已明確指出：盆地地形、人口密集、老化、少子化、都市熱島與極端高溫，是嚴峻課題；臺北的淨零自治條例也明確定義了熱島效應。這是非常適合做「風險監測殼」的題型。([臺北永續發展資訊網][3])

情境 A
熱浪來時，哪些里同時滿足「高齡人口高、綠覆低、建成環境蓄熱高、避暑資源不足」？

情境 B
雙北高溫警戒時，如何決定哪些區先投放關懷訪視、避暑據點宣導、戶外工作風險提醒？

AI 缺口
政府通常有資料，但缺「跨圖說明」能力。也就是，缺一個能把熱區、脆弱人口、公共設施、醫療支援與歷史事件同步解釋的 AI 輔助層。

### 需求 prompt 2

```md
# 任務名稱
雙北高溫熱島與脆弱族群保護儀表板研究

# 背景
臺北盆地熱島效應明確，高溫熱浪對高齡者、慢性病族群、戶外工作者與低綠覆區居民風險更高。雙北需要的不只是溫度地圖，而是結合人口脆弱性、設施可近性與應變資源的決策面板。

# 目標
建立一份適合黑客松 MVP 的規格文件，核心是找出：
1. 高溫暴露高風險區
2. 資源缺口區
3. 雙北跨區支援與應變優先序

# 工作編排
- Gemini CLI：搜尋雙北氣象、熱島、綠覆、避難與冷卻設施、人口年齡結構、醫療資源、官方高溫政策文件
- Codex CLI Worker 1：整理成問題定義、資料 schema、圖表方案、AI 說明稿
- Codex CLI Worker 2：驗證資料是否真有 API / CSV / GeoJSON、欄位是否可 join、文件是否前後一致
- Claude Sonnet 4.6：用政府評審方法論審查，強化成「No PPT 也能講清楚」的決選版

# 必要輸出
1. 風險分層邏輯
2. 脆弱族群 proxy 指標
3. 圖表與地圖設計
4. AI 摘要與警示語句模板
5. 資料清理流程
6. 可 PR 回官方 dashboard 的模組建議

# 限制
- 不做個人健康判讀
- 不做不可驗證的未來災害預言
- AI 只讀取已驗證的聚合指標與地圖狀態
```

## 3. 雙北跨區通勤壅塞、運輸韌性與事件應變

這題非常符合雙北共融。新北與臺北的通勤、捷運、公車、道路、生活圈是交纏的。黑客松如果出「跨區」題，交通幾乎必然是高分候選，尤其官方城市儀表板本身已有前後端、資料庫與圖磚架構，適合接交通類元件。([citydashboard.taipei][4])

情境 A
捷運/公車事故或豪雨造成轉乘瓶頸時，哪些行政區會被連帶放大衝擊？

情境 B
平日通勤尖峰下，雙北哪些跨區節點長期壅塞，但目前決策只看到單點而看不到跨線外溢？

AI 缺口
不是缺預測模型本身，而是缺一個能從多來源交通資料、事件資料與人流特徵，快速生成「替代路徑建議、受影響行政區摘要、韌性比較」的語意層。

### 需求 prompt 3

```md
# 任務名稱
雙北跨區通勤壅塞與運輸韌性儀表板研究

# 背景
雙北通勤不是單一城市問題，而是跨區生活圈問題。我要研究一個可在黑客松時限內完成的 MVP，能讓評審一眼看到：
1. 哪些跨區節點最脆弱
2. 哪些事件會造成外溢衝擊
3. 哪些替代運輸路徑或資源調度最有價值

# 工作編排
- Gemini CLI：搜尋雙北捷運、公車、道路、事故、降雨、即時或歷史運輸資料，以及官方 dashboard 既有交通組件
- Codex CLI Worker 1：撰寫需求 spec，特別強調雙北共融與決策價值
- Codex CLI Worker 2：檢查資料可用性、欄位對接、事件驅動邏輯與文件統整性
- Claude Sonnet 4.6：從評審視角重構成高分提案，補足 AI 功能邊界、圖表互動腳本與答辯口徑

# 輸出要求
1. 問題定義與使用者角色
2. 交通資料源與更新頻率
3. 圖表組合：流量、事件、外溢、比較、替代路徑
4. AI 功能：異常摘要、事件影響說明、跨圖決策壓縮
5. 開源整併策略
6. Demo 劇本

# 限制
- 不要承諾真實導航等級精度
- 不把 LLM 當路徑演算法
- 所有建議都要能回指資料或已知規則
```

## 4. 雙北兒少與青年心理健康風險早期辨識

這題很強，因為臺北教育局已有校園心理健康促進與高關懷學生早期辨識規劃；新北也明確在心理健康韌性城市與校園通 App 中推動數位心理健康量測與轉介。這代表題目有政策需求，也有 AI 切入空間。([台北市政府][5])

情境 A
校園、社政、衛政各自有高風險訊號，但缺乏跨局處視角去看「哪類地區、哪類族群、哪類資源斷點」最該先補。

情境 B
青少年求助資源很多，但入口分散，政府缺一個能把服務地圖、風險族群輪廓、與可近性缺口說清楚的 dashboard。

AI 缺口
缺的是「風險訊號摘要與資源導引層」，不是情緒判案器。AI 應用應放在聚合資料分析、資源缺口解釋、服務路徑摘要，而非個人心理診斷。

### 需求 prompt 4

```md
# 任務名稱
雙北兒少與青年心理健康風險早期辨識與資源導引儀表板研究

# 背景
雙北皆已重視校園心理健康、高關懷學生辨識、跨局處轉介與數位心理健康工具，但目前常見缺口是資料分散、資源地圖分散、難以快速看見哪裡最需要補強。

# 目標
設計一個不碰個資、不做個人診斷，但能支援政策與資源配置的儀表板研究方案，回答：
1. 哪些區域或年齡層風險訊號較高
2. 哪些資源類型不足
3. 哪些轉介或服務可近性存在缺口

# 工作編排
- Gemini CLI：搜尋雙北官方心理健康、教育、社政、衛政、校安、資源據點、服務量能與公開統計
- Codex CLI Worker 1：撰寫需求文件，強調公共決策用途與倫理邊界
- Codex CLI Worker 2：驗證資料是否適合公開儀表板使用，檢查欄位一致性與敘事完整性
- Claude Sonnet 4.6：以決選評審標準重新整理，強化應用價值、風險控管與答辯說法

# 必要輸出
1. 問題定義
2. 資料與倫理邊界
3. 圖表與地圖設計
4. AI 功能說明
5. 可 PR 模組
6. 評審可能質疑與回答

# 限制
- 不做個人風險打分
- 不做診斷或自動派案
- AI 只做聚合層級摘要、比較、轉介與資源建議草稿
```

## 5. 雙北災害避難、弱勢名冊與物資收容調度

這題非常有政府感，而且很適合「風險監測 + 資源分配 + 趨勢比較」三個殼一起用。臺北氣候調適文件明確指出極端高溫、強降雨、水患等風險；新北各區防災計畫也直接提到避難弱勢族群、跨縣市應變與臨時收容。([臺北永續發展資訊網][3])

情境 A
豪雨、颱風、土石流或淹水警戒時，哪些區的避難弱勢族群與收容處所、物資、交通可達性不匹配？

情境 B
災時雙北接壤區域需要跨區支援，但目前很難快速用資料說明「誰先支援誰、缺的是床位、車輛還是物資」。

AI 缺口
缺的是「跨圖統整與應變建議生成」：災況、人口、收容、物資、交通、醫療資料往往都在，但缺一個能在 1 分鐘內生成應變摘要的輔助層。

### 需求 prompt 5

```md
# 任務名稱
雙北災害避難弱勢族群與物資收容調度儀表板研究

# 背景
雙北面對豪雨、高溫、淹水與複合災害時，真正困難的不是單一資料不存在，而是弱勢名冊、避難收容、醫療支援、交通中斷與物資分配很難被放在同一個決策畫面。

# 目標
提出一個黑客松可完成的 MVP 研究方案，聚焦：
1. 哪些地區災時風險高
2. 哪些收容或物資存在缺口
3. 雙北跨區應援順序如何說明

# 工作編排
- Gemini CLI：搜尋雙北災害防救、避難收容、弱勢族群 proxy、淹水/坡地/熱浪/醫療/交通相關官方資料
- Codex CLI Worker 1：撰寫完整需求 spec，含圖表、資料流、AI 功能與 demo 情境
- Codex CLI Worker 2：檢核資料可用性、更新頻率、區域對映與文件一致性
- Claude Sonnet 4.6：以政府官員兼決選評審的方法論，審查是否真的可用於公共決策與賽後 PR

# 必要輸出
1. 災害情境與使用者故事
2. 資料源與欄位 mapping
3. 地圖與圖表設計
4. AI 應變摘要模板
5. 開源整併計畫
6. 風險限制與倫理說明

# 限制
- 不做個人層級追蹤
- 不做未經驗證的災損預言
- AI 只能根據儀表板已驗證資料做摘要與建議草稿
```

# 五題的評審排序建議

若以「政府迫切性 × 雙北共融 × AI 合理性 × 開放資料可做性 × 黑客松可完成度」來排序，我會這樣排：

1. 高齡長照與跨區醫療量能錯配
2. 高溫熱島與脆弱族群保護
3. 災害避難弱勢族群與物資收容調度
4. 跨區通勤壅塞與運輸韌性
5. 兒少與青年心理健康資源導引

原因很直接。
高齡、熱浪、防災這三題最容易同時滿足「公共急迫性」與「AI 不會變噱頭」。交通也強，但容易被做成一般智慧交通 dashboard。心理健康題很有價值，但資料與倫理界線比較容易踩線，必須更小心只做聚合層級與資源導引。
