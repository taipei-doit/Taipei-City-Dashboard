針對您已經 clone 好專案，想要從零開始設定環境與儀表板，以下是根據官方技術規範為您整理的設定步驟與注意事項：

### 第一步：基礎環境確認
在開始設定之前，請先確保您的開發環境符合以下條件：
*   **作業系統**：如果您使用的是 Windows，必須支援並設定好 **WSL2 環境**。
*   **技術棧確認**：前端使用 Vue 3 與 Vite；後端使用 Go / Gin；資料庫與快取會用到 PostgreSQL 與 Redis。
*   **Docker 注意事項**：若使用 Docker 啟動服務，請嚴格避免 Port 佔用衝突。

### 第二步：環境變數（ENV）設定
API 串接與密鑰管理有嚴格的安全規範，**嚴禁將 API Key 直接寫死在程式碼中**，必須透過環境變數（ENV）來設定。請在您的專案根目錄或對應的環境設定檔中加入以下參數：
*   `TWCC_API_URL`：設定為 `https://api-ams.twcc.ai/api`。
*   `TWCC_API_KEY`：填入您申請到的台智雲試用金鑰（比賽當天會發放正式專用 Key）。
*   `TWCC_MODEL`：強制指定為 `llama3.3-ffm-70b-16k-chat`，不得使用其他模型。
*   `TIMEOUT`：設定為 `60`。
*   `MAX_RETRY`：設定為 `2`。

### 第三步：儀表板與資料庫關聯設定（核心）
**⚠️ 警告**：切勿輕易重跑資料庫初始化指令，以免將現有資料清空。

「臺北城市儀表板 3.0」採用多城市架構，儀表板的設定會被拆分在四張資料表中，您必須依照以下邏輯來設定您的儀表板組件：
1.  **Component（組件基本資訊）**：先建立組件的核心名稱與基礎資訊。
2.  **Query Chart（各城市獨立設定）**：設定資料來源、SQL 語法與更新頻率。
    *   **關鍵設定**：必須填寫 `CT` (City) 欄位。臺北市資料設為 `Taipei`；雙北資料設為 `Metro-Taipei`。
    *   **避坑指南：**如果您要建立雙北（`Metro-Taipei`）的組件，**系統強制規定一定要預先搭配一筆臺北（`Taipei`）的設定**，否則切換顯示時會出錯。
3.  **Component Chart（圖表共用樣式）**：設定圖表類型與顏色。雙北與臺北會**共用同一套樣式**，請確保兩者的資料格式能互相兼容。
    *   *新功能提示*：若想使用「文字單位圖（Text Unit Chart）」，需在 Query Chart 將 Query Type 設為 `3D`，並透過 SQL 查詢的 icon 欄位定義單位（如：人數、%）。
4.  **Component Maps（地圖圖層設定）**：若組件包含地圖（Mapbox），需透過 Query Chart 內的 `MapConfig IDs` 欄位與此表串聯，以載入對應的視野與圖層。

### 第四步：啟動服務與開發紅線提醒
當環境與資料庫配置完成後，即可啟動前後端服務。前端統一呼叫後端封裝後的端點（Gateway 會處理後續流量），主要的 AI 服務端點為 `POST /api/v1/ai/chat/twai`。

最後，在開發過程中請務必遵守以下「技術紅線」，否則會被取消資格：
*   **套件限制**：`package.json` 或 `go.mod` 僅限使用白名單內的第三方套件。嚴禁私自引入未經審核的外部程式庫。
*   **圖表限制**：前端**不可使用 Apexcharts 以外的第三方圖表套件**來進行組件優化。
*   **流量限制**：系統對每隊有嚴格的流量控管（限制 30 RPM），請勿進行異常請求或壓力測試。
