# 計畫：組件快速驗證器 + 開發流程缺口修補

## Context

每次驗證前端組件可行性都要起 30GB Docker stack（Qdrant 20GB + PostgreSQL + ONNX 模型），但使用者只是想快速確認「這個想法能不能做成組件」。需要一個零基礎設施的驗證路徑，同時修補開發流程中的缺口（OMC 回報斷裂、缺少專案 context 等）。

---

## 一、新建 Skill：component-quick-validator

**檔案**：`.agents/skills/component-quick-validator/SKILL.md`

### 核心理念
不啟動 Docker、不跑後端、不碰資料庫。用 curl + 自包含 HTML + Claude Preview MCP 完成驗證。

### 4 Phase 流程

| Phase | 做什麼 | 工具 |
|-------|--------|------|
| 0 | 讀取 component-specs.md 目標組件規格 | Read |
| 1 | curl 驗證 API 可達性（HTTP status、欄位、座標格式、筆數） | Bash(curl) |
| 2 | 產生自包含 HTML（ApexCharts CDN + Mapbox CDN + 真實/mock 資料） | Write |
| 3 | Claude Preview 開啟 HTML → 截圖驗證視覺 + 合規檢查 → 輸出報告 | MCP Preview |

### HTML 預覽包含
- ApexCharts 圖表（嚴格對應規格的 chart type）
- Mapbox GL 地圖（座標、圖層、顏色）
- 城市切換下拉（台北/雙北）
- AI 面板 placeholder（可收合）
- 深色主題（`#1e1e1e` 背景）

### 報告輸出路徑
`docs/hackathon/01_heat_island/execute/validation-reports/component-{N}-quickval.md`

### 與 agent-harness-construction 的關係
- quick-validator = 可行性門檻（幾分鐘）
- agent-harness-construction = 正式開發流程（幾小時）
- 報告顯示 "Ready for Harness: YES" → 建議切換到正式開發
