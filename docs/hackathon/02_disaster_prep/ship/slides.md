# 災前情境劇本庫
## 雙北複合災難決策支援系統

**可行性研究報告**

臺北城市儀表板大黑客松 2026
日期：2026 年 4 月

---

## 問題：災害當下的決策困境

> 「颱風登陸前 2 小時，指揮官面前有 7 個不同系統的畫面。」

- **資訊碎片化**：氣象、交通、避難、輿情各自孤島
- **決策延遲**：臨時整合資料，黃金應變時間流失
- **副作用盲區**：下令關水門，交通壅塞無人預警

**核心問題：政府不缺資料，缺的是 30 秒內能做決策的整合畫面。**

---

## 解決方案：預製情境劇本庫

```
指揮官選劇本 → 30 秒內看到
├── 風險地圖（淹水 + 疏散路徑）
├── 輿情預測（民意波動 + 謠言熱點）
├── 決策卡片（建議行動 + 副作用警告）
└── 時間軸（T-72h → 應變中）
```

**預製 5 個復合災難情境**，覆蓋颱風、淹水、地震主要災型
**AI 角色**：摘要、比較、話術草稿——不做黑箱預測

---

## 目標使用者

| 角色 | 需求 | 系統支援 |
|------|------|---------|
| **應變指揮官** | 直覺決策、低認知負荷 | 3 KPI + 決策卡片 |
| **局處長/科長** | 細節資料、資源調度 | 可展開細節層 |
| **TBDC 工程師** | 穩定 API、標準 schema | OpenAPI + 模組化設計 |

**雙北共融**：整合 data.taipei + data.ntpc，跨河走廊疏散同步

## MiroFish 輿情模擬

**三種輸入種子**：
- 過去：歷史颱風新聞、NCDR 災損紀錄、納莉/蘇迪勒案例
- 現在：CWA、data.taipei、TDX 即時 API
- 未來：預製復合災難假設文件（合成 proxy）

**模擬角色**：市民、媒體記者、官方發言人、里長、專家

**輸出**：輿情時間序列、謠言擴散熱點、官方話術建議草稿

**展示亮點**：「若延遲 30 分鐘發布警告，謠言指數上升 45%」

## 技術風險與對策

| 層 | 主要風險 | 對策 |
|----|---------|------|
| **前端** | 資訊過載、地圖卡頓 | 預設 3-5 KPI、圖層分級載入 |
| **MiroFish** | LLM 幻覺、輸出不穩 | GraphRAG 嚴格檢索 + 模板化 |
| **MATSim** | 48h 路網太大跑不完 | 只做關鍵走廊，5 個預製劇本 |
| **資料** | API 更新頻率不一致 | 分層快取，靜態 + 即時雙模式 |

**AI 邊界**：摘要 ✅ 比較 ✅ 話術草稿 ✅ / 個人預測 ❌ 黑箱評分 ❌

## 資料清理流程（6 步驟）

**Layer A — 即時 API**：CWA 氣象/地震、data.taipei 淹水感測、TDX 交通
**Layer B — 靜態參考**：雙北避難收容、人口老化指數（年度預下載）
**Layer C — 歷史種子**：NCDR 災損、颱風新聞（丟給 MiroFish）

```
Step 1  拉取 + 快取 → PostgreSQL（標記 source、fetched_at）
Step 2  地理編碼標準化 → 全部轉 WGS84 + 行政區碼（5碼）
Step 3  欄位對映驗證 → 統一 schema，計算脆弱性 proxy
Step 4  Join：避難缺口 = 脆弱人口 - 總收容容量
Step 5  合成 proxy 文件 → 每個劇本的未來假設情境種子
Step 6  寫入 Component/QueryChart（CT=Metro-Taipei）
```
