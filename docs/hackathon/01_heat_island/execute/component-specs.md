## SYS.06 文化共融（3 個組件）

### 組件 1：雙北藝文活動即時地圖

**一句話：** 雙北所有進行中 / 即將舉辦的藝文活動，一張地圖即時呈現。

**目標使用者：** 想找週末活動的市民、觀光客、文化局承辦人

**資料源：**

| 城市 | 資料集 | 格式 | 更新頻率 |
|------|--------|------|---------|
| 台北 | 臺北市藝文活動（data.taipei） | JSON | 每日 |
| 台北 | 臺北旅遊網-景點資料 | JSON | 每週 |
| 新北 | 新北市藝文活動（data.ntpc.gov.tw） | JSON | 每日 |
| 全國 | 文化資料開放服務網 opendata.culture.tw | JSON API | 即時 |

**視覺化設計：**
- **地圖圖層**（Mapbox）：活動點位以類型色標顯示
  - 音樂 🎵 藍 / 展覽 🎨 紫 / 市集 🛒 橙 / 戲劇 🎭 紅 / 親子 👶 綠
- **圖表**：ColumnChart — 各區活動數量排行（台北 vs 新北 雙色對照）
- **互動**：
  - 時間篩選器：今天 / 本週末 / 下週 / 自訂日期
  - 類型篩選器：多選 tag
  - 點擊 pin → 彈出活動卡片（時間、地點、票價、交通建議）

**雙北切換：**
- CT = `Taipei`：只顯示台北市活動
- CT = `Metro-Taipei`：顯示台北 + 新北全部活動
- 切換時 ColumnChart 同步更新

**AI 洞察（Tool Calling）：**

```
Tool: summarize_events
Input: { city: "Metro-Taipei", date_range: "this_weekend" }
Output: "本週末雙北共有 52 場藝文活動。台北集中在中正、大安（展覽為主），
        新北集中在板橋、淡水（戶外市集為主）。建議關注：大稻埕國際藝術節
        （週六開幕）和板橋 435 藝文特區親子工作坊。"
```

**AI 進階 — 半自動決策輔助：**
- 文化局視角：「本月新北藝文活動數量較台北少 35%，建議增加板橋、中和區的活動場次」
- 民眾視角：「你正在看的大安區本週有 8 場免費展覽，是全雙北免費活動最密集的區域」

**PR wedge：** `EventMapComponent` — 即時活動聚合地圖元件（可套用於任何城市活動資料）

### 組件 2：景點人潮即時燈號

**一句話：** 即時顯示雙北熱門景點/商圈的人潮擁擠程度，紅黃綠燈號一目瞭然。

**目標使用者：** 出門前想避開人擠人的市民、觀光局分流調度

**資料源：**

| 城市 | 資料集 | 格式 | 更新頻率 |
|------|--------|------|---------|
| 台北 | 臺北市景點人潮即時燈號 | JSON | 即時（5-10min）🔥 |
| 新北 | 新北市觀光景點人潮統計（若有） | JSON | 待驗證 |

**視覺化設計：**
- **地圖圖層**（Mapbox）：各景點/商圈以燈號色圈顯示
  - 🟢 舒適（< 50%容量）/ 🟡 略擠（50-80%）/ 🔴 擁擠（> 80%）
- **圖表**：
  - GaugeChart — 選定景點的即時人潮百分比
  - TimelineSeparateChart — 過去 24 小時人潮趨勢（找出「黃金時段」）
- **互動**：
  - 點擊景點 → 展開即時人數 + 24hr 趨勢圖
  - 排行榜模式：全部景點按擁擠度排序

**雙北切換：**
- CT = `Taipei`：台北景點燈號
- CT = `Metro-Taipei`：含新北觀光景點（若資料可得則合併，否則標註「新北資料更新較慢」）

**AI 洞察（Tool Calling）：**

```
Tool: analyze_crowd
Input: { location: "西門町", time: "now" }
Output: "西門町目前人潮為紅燈（約 85% 容量），過去 3 小時持續上升。
        歷史數據顯示週六下午 2-5 點為尖峰，建議改往鄰近的中山站商圈
        （目前黃燈 62%）或大稻埕（綠燈 38%）。"
```

**AI 進階 — 決策輔助：**
- 「白晝之夜期間，中正區人潮已達紅燈。建議透過社群推播引導人流至大同區（目前綠燈），預計可分散 20% 人潮。」
- **副作用提示**：「若導流至大同區，該區夜市周邊停車場將在 30 分鐘內飽和」

**PR wedge：** `CrowdHeatmapComponent` — 即時人潮燈號地圖元件

### 組件 3：雙北文化設施密度比較

**一句話：** 比較雙北各行政區的文化設施（圖書館、博物館、藝文中心、電影院）密度，找出文化資源沙漠。

**目標使用者：** 文化局規劃者、關心社區的市民

**資料源：**

| 城市 | 資料集 | 格式 |
|------|--------|------|
| 台北 | 臺北市藝文館所（data.taipei） | JSON |
| 台北 | 臺北市各區圖書館 | JSON |
| 新北 | 新北市圖書館 / 藝文場館 | JSON |
| 全國 | 文化部文化設施資料 | JSON |

**視覺化設計：**
- **DistrictChart**（行政區色階圖）：每萬人文化設施數，深色=密、淺色=疏
- **RadarChart**：選定區域的文化資源雷達（圖書館/博物館/展演空間/電影院/社區文化中心）
- **BarPercentChart**：各區 vs 全市平均的差距

**雙北切換：**
- CT = `Taipei`：台北 12 區
- CT = `Metro-Taipei`：台北 12 區 + 新北 29 區，同一色階

**AI 洞察（Tool Calling）：**

```
Tool: compare_cultural_density
Input: { district_a: "大安區", district_b: "林口區" }
Output: "大安區每萬人擁有 3.2 個文化設施，是林口區（0.8 個）的 4 倍。
        林口區最缺的是展演空間（0 個）和社區文化中心（僅 1 個）。
        建議優先在林口增設多功能藝文空間，以服務近年大量遷入的年輕家庭。"
```

**PR wedge：** `DensityComparisonComponent` — 設施密度比較元件（可套用醫療、教育等任何設施類型）

| 城市 | 資料集 | 格式 | 更新頻率 |

**視覺化設計：**
- **地圖圖層**（Mapbox）：
  - AED 點位（❤️ 圖示）
  - 以場所分類色標：公共機關/交通場站/商場/學校/醫療院所

- **圖表**：
  - DistrictChart — 各區每萬人 AED 數量（色階圖）
  - BarChart — 台北 vs 新北各區 AED 密度排行

**雙北切換：**
- CT = `Taipei`：台北 AED
- CT = `Metro-Taipei`：合併雙北全部 AED，統一座標格式

**AI 洞察（Tool Calling）：**

```
Tool: analyze_aed_coverage
Input: { city: "Metro-Taipei", focus: "coverage_gaps" }
Output: "雙北共有 4,328 台 AED。台北每萬人 16.2 台，新北僅 8.7 台。
        覆蓋缺口最大的區域：新北林口區（每萬人 4.1 台，且多集中在
        三井 Outlet 附近，住宅區覆蓋率僅 23%）。建議優先在林口、
        三峽住宅區增設公共 AED。"
```

**AI 進階 — 決策輔助：**
- 衛生局視角：「若在林口區增設 15 台 AED（預算約 75 萬），可將 500m 覆蓋率從 23% 提升至 68%」

**PR wedge：** `FacilityCoverageMapComponent` — 設施覆蓋半徑分析地圖元件

## SYS.02 韌性防災（4 個組件）— AI 決策核心展示

### 組件 7：災難情境劇本選擇器

**一句話：** 預製 3-5 個復合災難情境劇本，點選即展開完整風險地圖 + 時間軸 + 決策建議。

**目標使用者：** 應變指揮官、局處長/科長、防災教育

**資料源：**

| 類別 | 資料集 | 更新頻率 |
|------|--------|---------|
| 預警 | CWA 氣象預報（雷達、雨量） | 即時 10-60min |
| 地震 | CWA 地震速報 E-A0015-001 | 秒級觸發 |
| 歷史 | NCDR 歷年淹水點/災損 | 歷史存檔 |
| 歷史 | 新北遭受災害救助情形 05e9a748 | 年度 |

**預製劇本：**

| ID | 劇本 | 災害類型 | 聚焦區域 |
|----|------|---------|---------|
| 001 | 強颱 + 淡水河氾濫 + 停電 | 颱風/淹水/停電 | 大安、萬華、板橋 |
| 002 | 地震 + 火警 + 幹道中斷 | 地震/火災/交通 | 台北核心 + 跨河走廊 |
| 003 | 颱風 + 大潮 + 捷運停駛 | 颱風/潮汐/交通 | 淡水線沿線 |
| 004 | 颱風後熱浪 + 停水 | 熱浪/停水 | 雙北全域 |
| 005 | 地震 + 豪雨 + 土石流 | 地震/土石流 | 新店、烏來、汐止 |

**視覺化設計：**
- **劇本卡片牆**：5 張卡片，每張顯示災害圖示 + 風險等級 + 受影響人口
- **點選後**：
  - 地圖自動切換到劇本的影響範圍（Mapbox 疊圖）
  - 時間軸（TimelineSeparateChart）：T-72h → T+應變中
  - KPI 面板：總報案數/警戒區數/收容所空位率

**雙北切換：**
- 所有劇本天然跨雙北（跨河走廊、通勤廊道）
- CT = `Taipei`：只看台北市影響範圍
- CT = `Metro-Taipei`：完整復合影響範圍

**AI 洞察（Tool Calling）：**

```
Tool: compare_scenarios
Input: { scenario_a: "001", scenario_b: "005" }
Output: "劇本 001（颱風淹水）與 005（地震土石流）比較：
        001 影響人口較多（約 82 萬人 vs 12 萬人），但 005 的
        致命風險更高（土石流致死率遠高於都市淹水）。
        兩者共同瓶頸：中正橋為唯一跨河疏散路徑。
        建議：兩劇本都應預置中正橋替代方案。"
```

**AI 進階 — 自動產出洞察：**
- 選擇劇本後，AI 自動生成 3 點「指揮官 30 秒摘要」
- 自動標出「本劇本最薄弱的決策點」
- 自動比對歷史相似案例（納莉/蘇迪勒）

**PR wedge：** `ScenarioSelectorComponent` — 劇本選擇器元件 + `scenario.schema.json`

  - 行政區底色 = 收容缺口嚴重度（紅=缺口大、綠=充足）
- **圖表**：
  - BarChart — 各區「脆弱人口 vs 收容容量」雙柱對比
  - DistrictChart — 收容缺口率色階圖
  - TextUnitChart — 關鍵 KPI（總缺口人數/最危險區域/充足率最低區）

**雙北切換：**
- CT = `Taipei`：台北 12 區避難缺口
- CT = `Metro-Taipei`：雙北全域，可看到「新北哪些區的居民可能需要跨區避難到台北」

Tool: analyze_shelter_gap
Input: { city: "Metro-Taipei", vulnerability_weight: true }

**AI 進階 — 決策輔助：**
- 自動計算「若開放所有學校作為備用收容所」後的缺口變化
- 跨區調度建議：「大安區缺口可由鄰近信義區（盈餘 12%）和文山區（盈餘 8%）支援」

**PR wedge：** `GapAnalysisComponent` — 資源缺口分析元件（可套用醫療、教育等）

### 組件 10：AI 決策卡片（副作用視覺化）★ 核心展示組件

**一句話：** 當災害情境觸發時，AI 自動生成決策建議卡片，hover 時地圖即時高亮受影響區域（副作用視覺化）。

**目標使用者：** 應變指揮官（30 秒內理解風險並決策）

**這是比賽的核心差異化組件 — 評審明確說副作用視覺化是區分作品優劣的關鍵指標。**

**資料源：** 整合組件 7-9 的所有資料，加上 AI 分析層

**視覺化設計：**
- **決策卡片列**（右側面板）：
  ```
  ┌─────────────────────────────────────────┐
  │ 🔴 高優先：關閉中正橋車道              │
  │ 依據：淡水河水位 > 7.3m + MATSim 壅塞 95% │
  │ 預計效果：疏散效率提升 23%              │
  │ ⚠️ 副作用：忠孝橋負荷增加 40%          │
  │ 信心度：0.82（基於歷史 3 次相似事件）    │
  │ [採納] [延後] [查看替代方案]            │
  └─────────────────────────────────────────┘
  ```
- **地圖互動**（核心亮點）：
  - Hover 決策卡 → 地圖即時高亮：
    - 🟢 正面效果區域（疏散路線暢通段）
    - 🟠 副作用區域（壅塞轉移段）
    - 🔴 風險區域（淹水/斷橋）
  - 點擊「查看替代方案」→ 地圖切換顯示替代路徑

**AI 架構（Tool Calling Chain）：**

```
Step 1: Tool assess_situation
  → 整合當前所有感測器資料，判斷風險等級

Step 2: Tool generate_decisions
  → 基於風險等級 + 劇本庫，生成 3-5 個決策建議
  → 每個建議附帶：依據資料、預期效果、副作用清單

Step 3: Tool visualize_side_effects
  → 將副作用轉為地圖圖層座標
  → 返回 Mapbox layer spec（哪些路段/區域高亮）

Step 4: Tool generate_briefing
  → 30 秒指揮官摘要（3 點：現況/建議/風險）
```

**完整 AI 輸出範例：**

```json
{
  "briefing": "淡水河水位超警戒，建議立即關閉中正橋並啟動萬華區疏散。",
  "decisions": [
    {
      "priority": "critical",
      "action": "關閉中正橋雙向車道",
      "evidence": ["淡水河水位 7.5m（>警戒 7.3m）", "MATSim 壅塞預測 95%"],
      "expected_effect": "疏散效率 +23%",
      "side_effects": [
        {
          "description": "忠孝橋負荷增加 40%",
          "affected_area": {"type": "road", "coordinates": [...], "severity": "medium"},
          "map_layer": "side_effect_congestion"
        }
      ],
      "confidence": 0.82,
      "source_trace": ["CWA 水位 API", "MATSim 預跑結果 001", "歷史案例：納莉颱風"]
    }
  ]
}
```

**雙北切換：**
- 副作用常常跨城市（關閉台北的橋 → 影響新北的車流）
- CT 切換顯示不同城市視角的副作用影響

**PR wedge：** `DecisionCardComponent` + `SideEffectOverlayComponent` — 這是最有價值的 PR，因為副作用視覺化是儀表板 v3.0 的進化方向
