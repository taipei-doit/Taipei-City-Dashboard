# Smart Commute Idea: 雙北低碳運具充電補給覆蓋

## 背景

本構想對應黑客松六大主題中的「智慧交通」。官方既有儀表板已包含捷運人流、道路交通（擁擠、停車、施工、事故、監視器分布）與共享單車使用情況，因此本題避開上述範圍，改以「低碳運具充電補給覆蓋」切入智慧交通。

核心問題：

- 雙北哪些行政區的電動車/電動機車充電補給較不足？
- 哪些區域雖有站點，但即時可用槍數偏低？
- 不同行政區的充電規格、費率、開放狀態是否均衡？
- 政府若要新增充電設施，應優先補強哪些區域？

## 建議題目

**雙北低碳運具充電補給覆蓋儀表板**

此題不直接處理停車空位、道路壅塞、交通事故、施工、CCTV 或共享單車使用量，而是關注電動車與電動機車的充電補給基礎設施，屬於智慧交通中的低碳運具服務可近性。

## 四個組件

### 1. 充電站分布地圖

用途：

- 顯示臺北市、新北市、雙北合併範圍的充電站點。
- 支援行政區篩選、站點類型篩選、充電站詳情彈窗。
- 作為必要的地圖圖層組件。

主要指標：

- 站點數
- 充電樁數
- 站點行政區分布
- 站點經緯度

資料來源：

- 交通部 TDX「充電站之基本資料」
  - 政府資料開放平臺：https://data.gov.tw/dataset/170220
  - API 文件：https://tdx.transportdata.tw/api-service/swagger/basic/b378d320-04a9-4fba-80b8-0df1b96dd5e8#/CityEVCharging/ParkingEV_API_Station
  - 更新頻率：每 4 小時
  - 授權：政府資料開放授權條款-第 1 版
  - 可用欄位：充電站代碼、充電站名稱、地址、緯度、經度、充電樁數量、費率文字說明等

資料取得方式：

- 使用既有 data-end TDX 工具 `get_tdx_data` 與 `TDXAuth`。
- 分別查詢 `Taipei` 與 `NewTaipei`。
- 寫入 PostgreSQL current table，保留最新站點資料。

### 2. 即時可用充電槍

用途：

- 顯示目前可用、使用中、故障或不可用的充電槍狀態。
- 計算行政區與城市層級的即時可用率。
- 找出短時間內供給緊張的行政區。

主要指標：

- 充電槍總數
- 可用槍數
- 使用中槍數
- 異常/故障槍數
- 即時可用率

資料來源：

- 交通部 TDX「充電站之充電槍即時狀態資料」
  - 政府資料開放平臺：https://data.gov.tw/dataset/170224
  - API 文件：https://tdx.transportdata.tw/api-service/swagger/basic/b378d320-04a9-4fba-80b8-0df1b96dd5e8#/CityEVCharging/ParkingEV_API_ConnectorLiveStatus
  - 更新頻率：每 1 分鐘
  - 授權：政府資料開放授權條款-第 1 版
  - 可用欄位：充電站代碼、充電樁代碼、充電槍代碼、充電槍狀態、充電槍規格

資料取得方式：

- 使用 TDX API 每 5 到 10 分鐘更新一次，避免比賽環境與儀表板查詢壓力過高。
- ETL 將即時狀態與充電站基本資料用站點代碼關聯，補上城市、行政區、經緯度。
- 使用 `current+history` 載入模式，current table 支援 dashboard 查詢，history table 支援短期趨勢分析。

### 3. 充電規格與容量結構

用途：

- 分析雙北各行政區的充電設施規格組成。
- 區分快充/慢充、槍型、功率、汽車/機車補給服務。
- 呈現某些區域是否只有低功率或特定規格充電資源。

主要指標：

- 充電樁數
- 充電槍數
- 快充/慢充比例
- 槍型分布
- 最大功率分布
- 電動汽車與電動機車補給結構

資料來源：

- 交通部 TDX「充電站之充電樁基本資料」
  - 政府資料開放平臺：https://data.gov.tw/dataset/170221
  - API 文件：https://tdx.transportdata.tw/api-service/swagger/basic/b378d320-04a9-4fba-80b8-0df1b96dd5e8#/CityEVCharging/ParkingEV_API_ChargingPoint
  - 更新頻率：每 4 小時
  - 授權：政府資料開放授權條款-第 1 版
- 交通部 TDX「充電站之充電槍基本資料」
  - 政府資料開放平臺：https://data.gov.tw/en/datasets/170222
  - API 文件：https://tdx.transportdata.tw/api-service/swagger/basic/b378d320-04a9-4fba-80b8-0df1b96dd5e8#/CityEVCharging/ParkingEV_API_Connector
  - 更新頻率：每 4 小時
  - 授權：政府資料開放授權條款-第 1 版
- 新北市電動機車充電站
  - 資料頁：https://data.ntpc.gov.tw/datasets/e461bc62-34d2-42c5-a871-f2fc2fb88d01
  - 格式：JSON、CSV、XML
  - 可用欄位：行政區、站名、地址、類別、充電站狀況、是否收費、是否對外開放、充電座型式、充電插座數

資料取得方式：

- TDX 資料作為規格主資料。
- 新北市資料補強電動機車充電站型態與插座數。
- 若地方資料只有地址沒有座標，先以行政區聚合，不強制作點位地圖。

### 4. 費率與服務可近性

用途：

- 比較不同城市與行政區的收費型態與服務可近性。
- 呈現免費/收費比例、尖離峰費率、對外開放狀態。
- 找出高需求但費率資訊或開放性不足的區域。

主要指標：

- 有費率資料的充電槍數
- 免費/收費比例
- 尖峰/離峰費率分布
- 對外開放比例
- 行政區服務密度

資料來源：

- 交通部 TDX「充電站之充電槍充電費率資料」
  - 政府資料開放平臺：https://data.gov.tw/dataset/170223
  - API 文件：https://tdx.transportdata.tw/api-service/swagger/basic/b378d320-04a9-4fba-80b8-0df1b96dd5e8#/CityEVCharging/ParkingEV_API_ChargingRate
  - 更新頻率：每 4 小時
  - 授權：政府資料開放授權條款-第 1 版
- 臺北市營利型電動車充換電站資訊
  - 資料頁：https://data.taipei/dataset/detail?id=668313d7-bcfc-4c90-b769-e398b08a1b2d
  - 格式：CSV
  - 可用資料項目：營利電動機車換電站、營利電動機車充電站、營利電動車充電站
  - 可用欄位：序號、廠商、名稱、地址、縣市、縣市代碼
- 新北市電動汽車充電站
  - 資料頁：https://data.ntpc.gov.tw/datasets/1bb694e3-17c7-4ef0-ac75-52990c40edcd
  - 格式：JSON、CSV、XML
  - 可用欄位：站名、行政區、地址、類別、充電是否收費、充電座型式、充電插槍數

資料取得方式：

- TDX 費率資料用站點/樁/槍代碼關聯基本資料。
- 臺北與新北地方資料補足廠商、充換電類型、是否收費與地方統計。
- 地方資料若缺座標，採行政區彙整或用地址清理工具做後續補點。

## 資料可取得性結論

四個組件都有公開、合法、可驗證資料可用：

- 地圖點位：TDX 充電站基本資料有經緯度。
- 即時狀態：TDX 充電槍即時狀態每 1 分鐘更新。
- 規格容量：TDX 充電樁與充電槍基本資料每 4 小時更新。
- 費率與開放性：TDX 費率資料加上臺北/新北地方資料可支撐。

地方資料不建議單獨支撐地圖，因為部分資料只有地址與行政區，沒有明確經緯度。最穩定做法是地圖與即時狀態以 TDX 為主，地方資料作統計補強。

## AI Chat 整合方式

依 wiki，AI Chat 應由後端 gateway 串接 TWCC 模型，不應由前端直接呼叫模型。指定模型為 `llama3.3-ffm-70b-16k-chat`，後端可透過 tool calling 執行資料查詢，並將互動寫入 `ai_chatlog`。

建議流程：

1. Airflow ETL 從 TDX、data.taipei、data.ntpc.gov.tw 取得資料。
2. ETL 將資料清理後寫入 PostgreSQL。
3. Dashboard 元件查詢 PostgreSQL 呈現圖表與地圖。
4. AI Chat 不直接呼叫外部資料源，只透過後端 tools 查詢內部資料表。
5. 模型根據 tool 查詢結果產生自然語言解釋、比較與建議。

建議 AI tools：

### `get_ev_charging_summary(city, district)`

用途：

- 查詢指定城市或行政區的充電站數、槍數、可用槍數、可用率、收費比例。

範例問題：

- 「新北市新店區現在充電資源夠嗎？」
- 「臺北市哪一區可用充電槍最多？」

### `find_nearby_ev_chargers(lat, lng, radius, connector_type)`

用途：

- 根據經緯度、半徑與槍型找附近可用充電站。

範例問題：

- 「市府附近 1 公里內有沒有可用快充？」
- 「板橋車站附近有哪些充電站目前可用？」

### `compare_charging_coverage(metric, city_scope)`

用途：

- 比較雙北行政區的站點密度、可用率、規格覆蓋與費率資訊完整度。

範例問題：

- 「雙北哪五個行政區充電補給最不足？」
- 「臺北與新北的快充覆蓋差異在哪？」

### `explain_charging_anomaly(city, district)`

用途：

- 解釋某區即時可用率偏低、故障比例偏高或費率資訊不足的可能原因。

範例問題：

- 「為什麼中和區目前充電可用率偏低？」
- 「哪幾個區域需要優先新增充電設施？」

## AI Chat 展示情境

使用者可以直接問：

- 「幫我找雙北充電補給最不足的前 5 個行政區。」
- 「如果要新增 10 個充電站，應優先放在哪些區？」
- 「臺北市和新北市的快充資源哪裡差最多？」
- 「我在市府附近，現在去哪裡充電最可靠？」

AI 回答應包含：

- 依據哪些資料表或指標判斷。
- 目前數值摘要。
- 排名或候選區域。
- 政策或營運建議。
- 資料更新時間與限制。

## 風險與限制

- TDX API 需要 `TDX_CLIENT_ID` 與 `TDX_CLIENT_SECRET`。
- TDX 即時狀態更新頻率高，ETL 排程應避免過於頻繁造成壓力。
- 臺北/新北地方資料部分缺少經緯度，需用行政區聚合或地址轉座標補強。
- 地方資料更新頻率多為不定期，應在 dashboard 顯示資料更新時間。
- AI Chat 應查詢內部資料表，不應在使用者提問時即時打外部 API。

## 推薦 MVP

第一版先完成：

1. TDX 雙北充電站分布地圖。
2. 行政區站點數、槍數與可用率排行。
3. 充電規格與快慢充比例。
4. 費率/收費型態與服務可近性比較。
5. AI Chat 支援「摘要」、「排行」、「附近查詢」、「缺口解釋」四類問題。
