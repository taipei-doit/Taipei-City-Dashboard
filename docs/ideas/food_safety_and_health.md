# Food Safety and Health Idea: 雙北外食食安風險與安心選擇

## 背景

本構想對應黑客松六大主題中的「Food safety and health」。官方既有儀表板目前已包含長照據點、銀髮俱樂部、死因別死亡率、疫苗接種醫院數量、扶養比/老化指數、高齡就業人口年增結構、年齡分布等元件，因此本題避開高齡照護、人口結構、死因統計與疫苗院所，改以「外食與食品供應鏈的食安治理」切入。

核心問題：

- 雙北哪些行政區的食品業者密度高，但合格評核或稽查覆蓋較不足？
- 哪些食品類別或節慶專案較常出現抽驗不合格？
- 食品工廠、市場、餐飲店等供應節點在哪些區域集中？
- 民眾或政策人員要如何快速找到較安心的餐飲選擇與高風險區域？

## 建議題目

**雙北外食食安風險與安心選擇儀表板**

此題不直接處理長照、銀髮服務、死因、疫苗院所或人口高齡化，而是聚焦食品抽驗、餐飲衛生分級、食品業者登錄與食品供應節點。它符合「食品安全與健康」主題，也能用雙北比較呈現生活圈尺度的外食風險與治理量能。

## 四個組件

### 1. 食安風險行政區地圖

用途：

- 顯示臺北市、新北市、雙北合併範圍的行政區食安風險指標。
- 作為必要的地圖圖層組件。
- 用顏色呈現行政區風險分數，點選行政區後顯示食品業者數、抽驗不合格件數、通過評核店數與資料更新時間。

主要指標：

- 食品業者登錄數
- 食品抽驗不合格件數
- 通過餐飲衛生分級評核店數
- 每千家食品業者不合格件數
- 每千家食品業者通過評核店數

建議圖表：

- `DistrictChart` 或地圖圖層：行政區風險分數。
- `BarChart`：風險最高行政區排行。
- `MapLegend`：低、中、高風險分級。

資料來源：

- 衛福部食藥署「食品業者登錄資料集」
  - 政府資料開放平臺：https://data.gov.tw/dataset/8938
  - OAS/API 說明：https://data.fda.gov.tw/opendata/exportDataList.do?method=openDataApi&InfoId=97
  - 更新頻率：每 1 月
  - 授權：政府資料開放授權條款-第 1 版
  - 可用欄位：公司或商業登記名稱、統一編號、業者地址、食品業者登錄字號、登錄項目
- 臺北市「食品業者登錄數」
  - 資料頁：https://data.taipei/dataset/detail?id=9431f450-57d6-4c23-aca6-0ff50de49f0d
  - 可用欄位：項次、行政區、食品業者登錄數
- 新北市「食品業者登錄數」
  - 資料頁：https://data.ntpc.gov.tw/datasets/D67EC90F-2045-4FA1-A41E-1ABC6ABA62DD
  - API 格式：JSON、CSV、XML
  - 更新頻率：每季

資料取得方式：

- 以食藥署全國食品業者登錄資料為雙北共同底表，透過地址解析出城市與行政區。
- 臺北與新北的食品業者登錄數可作為官方彙總校驗。
- 風險分數先採行政區聚合，不需要即時打外部地理服務；若要做店家點位地圖，再用地址轉座標補點。

### 2. 食品抽驗不合格趨勢

用途：

- 追蹤雙北食品抽驗不合格案件的年度、月份與食品類別變化。
- 比較臺北、新北在節慶食品、生鮮肉品、蛋品、水產、即食食品等抽驗主題上的風險差異。
- 支援從「件數」切到「每千家食品業者不合格率」。

主要指標：

- 抽驗不合格件數
- 不合格原因類型
- 食品分類或專案名稱
- 抽驗地點行政區
- 每千家食品業者不合格件數

建議圖表：

- `TimelineStackedChart`：年度或月份不合格件數。
- `BarChart`：食品分類/不合格原因排行。
- `ColumnLineChart`：不合格件數與業者基數對照。

資料來源：

- 臺北市衛生局「食品抽驗不合格清冊」
  - 資料頁：https://data.taipei/dataset/detail?id=09a917a0-0fb5-47e1-957c-5f1268fba517
  - 更新頻率：每 1 年
  - 授權：公開
  - 可用欄位：專案名稱、抽驗日期、分類、檢體名稱、抽驗行政郵遞區號、抽驗地點、檢驗結果、不符合規定原因
- 新北市「食品抽驗資料」
  - 資料頁：https://data.ntpc.gov.tw/datasets/078cb722-15ac-4e1e-b541-e75bfe0aa440
  - API 格式：JSON、CSV、XML
  - 更新頻率：每月
  - 授權：政府資料開放授權條款-第 1 版
  - 可用欄位：序號、機構名稱、檔案名稱、網址、日期、時間

資料取得方式：

- 臺北資料可直接由 CSV 匯入，按日期、分類、行政區與不合格原因正規化。
- 新北資料的 API 主要提供每份抽驗名冊的公開檔案連結，ETL 需下載公開 PDF/檔案並解析表格；若時間不足，MVP 可先以檔案名稱解析年份、月份、食品主題與發布時間，並把細項解析列為第二階段。
- 兩市資料清理後寫入同一張 `food_inspection_failures` 表，欄位保留 `city`、`district`、`sample_date`、`category`、`item_name`、`failure_reason`、`source_url`。

### 3. 餐飲衛生分級評核覆蓋

用途：

- 呈現雙北通過餐飲衛生分級評核的店家分布。
- 比較「優」與「良」等級比例，以及各行政區通過評核店數相對於食品業者數的覆蓋程度。
- 協助民眾查詢安心外食區域，也協助政府判斷輔導資源是否集中在少數商圈。

主要指標：

- 通過評核店數
- 優級/良級比例
- 每千家食品業者通過評核店數
- 評核名單更新年度
- 行政區覆蓋率排行

建議圖表：

- `DistrictChart`：行政區通過評核覆蓋率。
- `BarPercentChart`：優級/良級比例。
- `TreemapChart` 或 `BarChart`：商圈/行政區店數分布。

資料來源：

- 臺北市「通過餐飲衛生管理分級評核業者」
  - 資料頁：https://data.taipei/dataset/detail?id=59579c19-a561-4564-8c0f-545bfb32c0f6
  - 更新頻率：每 1 年
  - 授權：公開
  - 可用欄位：行政區域代碼、業者名稱店名、食品業者登錄字號、地址、評核結果
- 新北市衛生局「餐飲衛生管理分級評核」
  - 公開頁：https://www.health.ntpc.gov.tw/basic/?node=19343
  - 目前公開多年度通過名單 PDF，例如 114、113、112 年度名單
  - 可用欄位需由 PDF 表格解析：店名、地址、行政區、評核等級、有效期限

資料取得方式：

- 臺北資料直接匯入 CSV。
- 新北資料從衛生局公開 PDF 解析；若 PDF 結構在比賽期間不穩定，MVP 可先匯入最新年度名單，並保留來源檔 URL 與解析日期。
- 用食品業者登錄數作分母，避免只看通過店數造成大行政區天然偏高。

### 4. 食品供應節點與稽查量能

用途：

- 結合食品工廠、公有市場、食品業者與稽查工作量，呈現雙北食品供應節點密度與治理壓力。
- 協助判斷哪些區域應優先增加抽驗、輔導或分級評核。
- 補足單純不合格案件數不足以反映風險暴露的問題。

主要指標：

- 食品工廠數
- 公有市場/超市數或攤位數
- 食品業者登錄數
- 食品衛生稽查家次
- 不合格飭令改善家次
- 稽查家次/食品業者數

建議圖表：

- `IndicatorChart`：行政區治理壓力分級。
- `ColumnLineChart`：稽查家次與改善家次趨勢。
- `BarChart`：食品供應節點密度排行。

資料來源：

- 臺北市「食品衛生管理工作」
  - 資料頁：https://data.taipei/dataset/detail?id=7d50657f-b35b-496e-b83f-5713893b9a9e
  - 收錄期間：1970-01-01 至 2025-12-31
  - 更新頻率：每 1 年
  - 可用欄位：食品衛生管理稽查家次、各業態稽查家次、不合格飭令改善家次、食品中毒人數
- 新北市「食品工廠清冊」
  - 資料頁：https://data.ntpc.gov.tw/datasets/c51d5111-c300-44c9-b4f1-4b28b9929ca2
  - API 格式：JSON、CSV、XML
  - 可用欄位：主管機關單位名稱、地址、稅號、TWD97、WGS84 經緯度、日期
- 臺北市「各區公有零售市(商)場攤位數」
  - 資料頁：https://data.taipei/dataset/detail?id=f490476d-d156-4492-a463-cf3405de3b55
  - 可用欄位：行政區、市場名稱、總計、蔬菜、青果、獸肉、漁產、家禽、飲食等攤位數
- 新北市「公有市場及超市清冊」
  - 資料頁：https://data.ntpc.gov.tw/datasets/785BE91A-CAAF-4E1C-91D6-F7D616D31A45
  - API 格式：JSON、CSV、XML
  - 可用欄位：名稱、縣市、行政區、地址、電話、類型

資料取得方式：

- 臺北稽查時間序列作為治理量能趨勢主資料。
- 新北若缺少同型稽查時間序列，可先用食品抽驗資料量、食品工廠、食品業者與公有市場資料建立供應節點密度與抽驗覆蓋 proxy。
- 市場與工廠資料以行政區聚合；有 WGS84 欄位者可作地圖點位第二階段。

## 資料可取得性結論

四個元件都有公開、合法、可驗證資料可用：

- 雙北共同底表：食藥署食品業者登錄資料集，可用地址篩出臺北市與新北市。
- 臺北食安資料：食品抽驗不合格、餐飲衛生分級、食品業者登錄數、食品衛生稽查時間序列皆在 data.taipei。
- 新北食安資料：食品抽驗資料、食品業者登錄數、食品工廠清冊、公有市場及超市清冊皆在 data.ntpc.gov.tw；餐飲衛生分級名單由新北市衛生局公開頁提供。
- 地圖元件：第一版建議用行政區風險地圖，避免地址轉座標造成比賽期間風險；第二版再做店家/工廠點位。

主要限制：

- 新北餐飲衛生分級名單目前較像公開 PDF 清冊，不是結構化 API，ETL 需要 PDF 表格解析與人工校驗。
- 新北食品抽驗資料 API 提供名冊連結，細項抽驗結果可能需要解析 PDF 或附件。
- 臺北與新北部分資料粒度不同，建議所有指標先正規化成行政區、年度、食品類別與來源 URL。

## AI Chat 整合方式

依 wiki，AI Chat 應由後端 gateway 串接 TWCC 模型，不應由前端直接呼叫模型。指定模型為 `llama3.3-ffm-70b-16k-chat`，後端可透過 tool calling 執行資料查詢，並將互動寫入 `ai_chatlog`。

建議流程：

1. Airflow ETL 從 data.taipei、data.ntpc.gov.tw、data.gov.tw/食藥署取得資料。
2. ETL 將資料清理成行政區、時間、類別、來源 URL 與更新時間欄位。
3. Dashboard 元件查詢 PostgreSQL 呈現圖表與地圖。
4. AI Chat 不直接呼叫外部資料源，只透過後端 tools 查詢內部資料表。
5. 模型回答時必須回報資料更新時間與限制，尤其是 PDF 解析資料。

建議 AI tools：

### `get_food_safety_summary(city, district, year)`

用途：

- 查詢指定城市或行政區的食品業者數、抽驗不合格件數、評核通過店數、風險分數。

範例問題：

- 「板橋區目前食安風險高嗎？」
- 「臺北市哪幾區食品抽驗不合格比較多？」

### `rank_food_safety_districts(metric, city_scope, year)`

用途：

- 依不合格率、評核覆蓋率、供應節點密度或治理壓力排序行政區。

範例問題：

- 「雙北食安風險最高的前 5 個行政區是哪些？」
- 「哪些區食品業者很多但通過評核比例偏低？」

### `find_certified_food_places(city, district, keyword, rating)`

用途：

- 查詢通過餐飲衛生分級評核的店家，支援行政區、店名關鍵字與優/良等級篩選。

範例問題：

- 「信義區有哪些優級餐廳？」
- 「新店區通過餐飲衛生分級的店家有哪些？」

### `explain_food_safety_signal(city, district, year)`

用途：

- 結合食品業者密度、抽驗不合格、分級評核覆蓋與供應節點，產出自然語言解釋與治理建議。

範例問題：

- 「為什麼中山區的食安風險分數偏高？」
- 「如果只能增加 20 家餐飲輔導，應優先放在哪些區？」

## AI Chat 展示情境

使用者可以直接問：

- 「幫我找雙北外食食安風險最高的前 5 個行政區。」
- 「臺北市和新北市哪裡的通過餐飲衛生評核覆蓋率差最多？」
- 「最近食品抽驗不合格主要集中在哪些食品類別？」
- 「我在板橋，想找通過餐飲衛生分級的店家。」

AI 回答應包含：

- 使用哪些指標與資料表。
- 指定城市或行政區的最新數值。
- 排名或候選名單。
- 政策或民眾行動建議。
- 資料更新時間與限制。

## 推薦 MVP

第一版先完成：

1. 行政區食安風險地圖，支援臺北市/雙北切換。
2. 食品抽驗不合格趨勢與類別排行。
3. 餐飲衛生分級評核覆蓋率。
4. 食品供應節點與稽查量能比較。
5. AI Chat 支援「摘要」、「排行」、「安心店家查詢」、「風險解釋」四類問題。
