# 低碳移動基礎建設缺口：電動汽車充電站、樁、槍分布

## 資料

### 資料來源

本組件以 TDX「綠色運輸-充電樁」CityEVCharging API 作為電動汽車充電基礎設施資料來源。資料層級分成「站、樁、槍」：

- 充電站 `Station`：一個充電服務地點，用於地圖點位與行政區站數。
- 充電樁 `ChargingPoint`：站內的一台充電設備，用於行政區設備數。
- 充電槍 `Connector`：樁上的實際充電接口，用於分析充電功率結構。

TDX Swagger：https://tdx.transportdata.tw/api-service/swagger/basic/b378d320-04a9-4fba-80b8-0df1b96dd5e8#/CityEVCharging

| TDX endpoint | operationId | 回傳陣列 | 主要欄位 | 用途 |
|--------------|-------------|----------|----------|------|
| `/v1/EV/Station/City/{City}` | `ParkingEV_API_Station` | `Stations` | `StationID`, `StationName`, `OperatorID`, `OperationType`, `PositionLat`, `PositionLon`, `Spaces`, `ChargingPoints`, `Connectors`, `ServiceTime`, `ParkingRate`, `ChargingRate`, `Floors`, `Location`, `Telephone`, wrapper `UpdateTime` | 地圖點位、行政區充電站數、站點彈跳資訊 |
| `/v1/EV/ChargingPoint/City/{City}` | `ParkingEV_API_ChargingPoint` | `ChargingPoints` | `StationID`, `ChargingPointID`, `OperatorID`, `Connectors`, `ChargingRate`, `Payment`, `StartType`, `Floor`, `UsageRestriction`, wrapper `UpdateTime` | 行政區充電樁數、站點設備數校正 |
| `/v1/EV/Connector/City/{City}` | `ParkingEV_API_Connector` | `Connectors` | `StationID`, `ChargingPointID`, `ConnectorID`, `Type`, `Power`, `Voltage`, `CurrentRating`, `PowerRating`, `Floor`, `UsageRestriction`, wrapper `UpdateTime` | 行政區充電槍功率比例 |

第一版抓取城市：

```text
https://tdx.transportdata.tw/api/basic/v1/EV/Station/City/Taipei?$format=JSON
https://tdx.transportdata.tw/api/basic/v1/EV/Station/City/NewTaipei?$format=JSON
https://tdx.transportdata.tw/api/basic/v1/EV/ChargingPoint/City/Taipei?$format=JSON
https://tdx.transportdata.tw/api/basic/v1/EV/ChargingPoint/City/NewTaipei?$format=JSON
https://tdx.transportdata.tw/api/basic/v1/EV/Connector/City/Taipei?$format=JSON
https://tdx.transportdata.tw/api/basic/v1/EV/Connector/City/NewTaipei?$format=JSON
```

TDX wrapper 的 `UpdateTime`, `SrcUpdateTime`, `AuthorityCode`, `Count` 需保留到 ETL metadata 或資料表欄位。資料內容時間優先使用 wrapper `UpdateTime`。

### TDX 欄位解讀

#### 充電站 Station

`Station` 是地圖與行政區站數的主表。`PositionLat` 與 `PositionLon` 是代表點座標；`Location.Address` 包含 `City`, `Town`, `Road`, `Lane`, `Alley`, `No`，可組合成地址與行政區。`ChargingPoints` 是該站充電樁數，`Connectors` 是依槍規格與 AC/DC 類型彙整的槍數陣列。

`StationName` 是物件型態，應優先取中文名稱欄位；若中文缺漏，再取英文或原始 JSON 字串。

#### 充電樁 ChargingPoint

`ChargingPoint` 透過 `StationID` 連回站，`ChargingPointID` 是樁代碼。此 endpoint 不提供座標與行政區，因此 ETL 需用 `StationID` join `Station` 取得 `city`, `district`, `wkb_geometry` 等空間欄位。

`ChargingPoint.Connectors` 只提供槍規格 `Type` 與數量 `Quantity`，不提供最大功率；功率比例圖應使用 `Connector` endpoint。

#### 充電槍 Connector

`Connector` 透過 `StationID` 與 `ChargingPointID` 連回站與樁。功率相關欄位如下：

| 欄位 | 說明 |
|------|------|
| `Type` | 充電槍規格：`1=CCS1`, `2=CCCS2`, `3=CHAdeMO`, `4=Tesla_TPC`, `5=J1772_Type1`, `6=Mennekes_Type2`, `254=Others`, `255=Unknown` |
| `Power` | 充電電力輸出方式：`1=AC`, `2=DC` |
| `Voltage` | 充電電壓，字串 |
| `CurrentRating` | 充電電流，字串 |
| `PowerRating` | 充電最大功率，字串 |

`PowerRating` 需清理成數值型 `power_kw`。若值含 `kW`、`KW` 或空白，ETL 需移除單位；若無法解析，歸入 `unknown` 功率級距。

## 前端
### 前端儀表板

前端儀表板支援 `臺北市` 與 `雙北` 城市範圍切換。切換城市範圍時，所有圖表依 `city_scope` 重新查詢或切換資料。

| 圖表 | query type | chart type | 顯示欄位 | 說明 |
|------|------------|------------|----------|------|
| 行政區充電站數量深淺圖 | `two_d` | `DistrictChart` | `x=district`, `y=station_count` | 以充電站地點數呈現行政區服務覆蓋 |
| 行政區充電樁數量深淺圖 | `two_d` | `DistrictChart` | `x=district`, `y=charging_point_count` | 以充電設備數呈現行政區供給容量 |
| 行政區充電槍功率比例長條圖 | `percent` | `BarPercentChart` | `x=district`, `series=power_bucket`, `y=connector_count` | 每個行政區一列，依充電槍最大功率級距顯示比例 |

充電槍功率級距建議第一版採固定 bucket：

| `power_bucket` | 規則 |
|----------------|------|
| `slow_ac` | `Power = 1` 或 `power_kw < 22` |
| `medium_dc` | `Power = 2` 且 `22 <= power_kw < 50` |
| `fast_dc` | `Power = 2` 且 `50 <= power_kw < 150` |
| `ultra_fast_dc` | `Power = 2` 且 `power_kw >= 150` |
| `unknown` | `PowerRating` 或 `Power` 無法判讀 |

若同一行政區沒有某個功率級距，仍需回傳 `0`，避免比例長條圖缺少 series。`percent` 查詢需依 `district`, `power_bucket_order` 排序，讓後端解析 categories 與 series 時保持穩定。

### 前端地圖圖層

前端地圖以充電站作為點位，不直接畫樁或槍。切換為 `臺北市` 時，只顯示臺北市站點；切換為 `雙北` 時，同時顯示臺北市與新北市站點。

地圖點擊充電站後，彈跳資訊顯示：

- 站名：`StationName`
- 城市與行政區：由 `Location.Address.City`、`Location.Address.Town` 或地址解析取得
- 地址：由 `Location.Address` 組合
- 營運業者：`OperatorID`
- 營運種類：`OperationType`
- 充電車位數：`Spaces`
- 充電樁數：`ChargingPoints` 或 join 後實際樁數
- 充電槍數：由 `Station.Connectors.Quantity` 加總，或 join `Connector` 後計算
- 服務時間：`ServiceTime`
- 停車費率：`ParkingRate`
- 充電費率：`ChargingRate`
- 充電槍功率摘要：依 `Connector.PowerRating` 彙整後顯示
- 資料時間：wrapper `UpdateTime`
- 資料來源：TDX CityEVCharging

地圖資料使用 WGS84/EPSG:4326 點位。若 `PositionLat` 或 `PositionLon` 缺漏，該站不得進入地圖圖層，但仍可在行政區統計中保留。

## 後端

後端需提供前端儀表板與地圖圖層兩類資料：行政區聚合圖表資料與充電站點位資料。圖表資料走既有 component chart query 流程，地圖圖層資料走 component map config 與 map query 流程。

### 行政區充電站數量圖

```sql
SELECT district AS x_axis, station_count AS data
FROM env_ev_charging_district_summary
WHERE city_scope = $1
ORDER BY district;
```

### 行政區充電樁數量圖

```sql
SELECT district AS x_axis, charging_point_count AS data
FROM env_ev_charging_district_summary
WHERE city_scope = $1
ORDER BY district;
```

### 行政區充電槍功率比例長條圖

```sql
SELECT
  district AS x_axis,
  power_bucket AS y_axis,
  connector_count AS data
FROM env_ev_charging_connector_power_district
WHERE city_scope = $1
ORDER BY district, power_bucket_order;
```

此查詢使用 `percent`，前端圖表建議使用 `BarPercentChart`。若現有 `BarPercentChart` 對多功率級距 series 支援不足，可先使用 `ColumnChart` 或 `BarChart` 呈現數量，後續再調整成比例顯示。

### 地圖圖層資料

```sql
SELECT
  station_id,
  station_name,
  city,
  district,
  address,
  operator_id,
  operation_type,
  spaces,
  charging_point_count,
  connector_count,
  power_summary,
  service_time,
  parking_rate,
  charging_rate,
  source_name,
  data_time,
  ST_AsGeoJSON(wkb_geometry)::json AS geometry
FROM env_ev_charging_stations
WHERE
  CASE
    WHEN $1 = 'taipei' THEN city = '臺北市'
    WHEN $1 = 'twin_city' THEN city IN ('臺北市', '新北市')
  END
  AND wkb_geometry IS NOT NULL;
```

資料端需把 TDX 來源資料清理成四種輸出：站點明細表、樁明細表、槍明細表、行政區聚合表。TDX API 透過專案既有 `utils.extract_stage.get_tdx_data` 取得資料，token 由 `utils.auth_tdx.TDXAuth` 從 Airflow Variables `TDX_CLIENT_ID` 與 `TDX_CLIENT_SECRET` 讀取。

### 行政區聚合表

建議資料表：`env_ev_charging_district_summary`

| 欄位 | 型別 | 說明 |
|------|------|------|
| `city_scope` | text | `taipei` 或 `twin_city` |
| `city` | text | 臺北市或新北市 |
| `district` | text | 行政區 |
| `station_count` | integer | 充電站數 |
| `charging_point_count` | integer | 充電樁數 |
| `connector_count` | integer | 充電槍數 |
| `data_time` | timestamptz | 資料內容時間 |

建議另建功率比例表：`env_ev_charging_connector_power_district`

| 欄位 | 型別 | 說明 |
|------|------|------|
| `city_scope` | text | `taipei` 或 `twin_city` |
| `city` | text | 臺北市或新北市 |
| `district` | text | 行政區 |
| `power_bucket` | text | 功率級距 |
| `power_bucket_order` | integer | 圖表排序 |
| `connector_count` | integer | 該功率級距槍數 |
| `connector_ratio` | numeric | 該行政區內比例，可供 AI 或 tooltip 使用 |
| `data_time` | timestamptz | 資料內容時間 |

聚合規則：

- `station_count` 以去重後 `StationID` 計算。
- `charging_point_count` 優先以 ChargingPoint endpoint 的去重 `ChargingPointID` 計算；若缺資料，才 fallback 到 Station `ChargingPoints`。
- `connector_count` 優先以 Connector endpoint 的去重 `ConnectorID` 計算；若缺資料，才 fallback 到 Station `Connectors.Quantity` 加總。
- 所有行政區與所有功率級距都需補 `0`，確保 DistrictChart 與比例長條圖資料完整。
- `taipei` 範圍只產生臺北市行政區資料。
- `twin_city` 範圍產生臺北市與新北市行政區資料。

### 資料更新與 metadata

ETL 每次更新後需同步更新 `dataset_info`。站點明細表支援地圖圖層，`dataset_info` 的 geometry 類型應標記為 `Point`，座標系統為 `EPSG:4326`。樁、槍與行政區聚合表不需 geometry，但需保留資料來源、更新頻率、資料時間與 ETL 說明。

## AI Chat 的結合方法

AI Chat 透過後端 tool calling 整合本組件，不直接讓前端呼叫資料庫。建議提供以下 tools：

| Tool | 參數 | 回傳 | 用途 |
|------|------|------|------|
| `get_ev_charging_summary` | `city_scope` | 站數、樁數、槍數、行政區排名、資料時間 | 回答整體供給與缺口 |
| `get_ev_charging_district_counts` | `city_scope` | 各行政區 `station_count`, `charging_point_count`, `connector_count` | 供 AI 解釋兩張深淺圖 |
| `get_ev_charging_connector_power_mix` | `city_scope`, `district` | 各行政區功率級距槍數與比例 | 供 AI 解釋功率比例長條圖 |
| `get_ev_charging_station_detail` | `station_id` | 站點、樁、槍、功率摘要、座標 | 供地圖點擊或使用者詢問單站資訊 |
| `set_ev_charging_view` | `city_scope`, `focus_district`, `focus_station_id` | 前端視圖控制指令 | 讓 AI 協助切換臺北/雙北、聚焦行政區或站點 |

Tool 參數規則：

- `city_scope` 只允許 `taipei` 或 `twin_city`。
- `district` 使用行政區中文名稱；未指定時代表全部行政區。
- `station_id` 必須是 TDX `StationID`。

AI 回答需附帶資料時間與資料來源，並在資料缺漏時明確說明限制。例如 Connector endpoint 無法解析 `PowerRating` 時，功率比例圖會把該筆歸入 `unknown`。
