# 評估報告：SYS.03 永續環境 (Target: 空品微型測站, 熱點用電與溫度資料)

## 1. 📊 快速評估雷達 (Score & Review)
* **A. 可用度 (15/40)**：⬇️ 降分。API 雖然存在，但 `tpdep` 延遲超過 340 分鐘，屬「殭屍資料」，無法支撐即時預警。
* **B. 決策張力 (20/40)**：⬇️ 降分。缺乏座標資料導致無法即時在地圖上對應位置，決策鏈斷裂。
* **C. 可信度 (10/20)**：⬇️ 降分。缺乏經緯度與微型站點的對應 Mother Table。
* **總分：45 分 ❌ 具備高開發風險**

## 2. 🎬 決策劇本 (Scenario)
**極端熱島效應**：當單一行政區室外溫度超過 38 度且微型空品測站 PM2.5 超標，下令開啟公共庇護降溫空間，連動台電停電風險警示。

## 3. 🛠️ 底盤期開發工具
* **空間網格化處理（Spatial Binning）**：點位過多，需撰寫腳本將空品點位轉為「Hexagon 網格圖層」。
* **自動主外鍵映射 (Joiner)**：須建立 `站名代號` 與 `經緯度` 的靜態映射表，補足 API coordinate null 的缺陷。

## 4. 🕵️ 資料 Integrity 深度診斷 (Data Profiling)
* **孤兒率 (Orphan Rate)**: 100% (動態資料中找不到座標欄位，無法直接投射)。
* **沉默延遲 (Staleness)**: 100% (所有測站均延遲 > 30 分鐘，平均延遲 347 分鐘)。
* **空間品質 (Spatial Quality)**: 0% (座標欄位 `Latitude`/`Longitude` 為空值)。

## 5. 🕳️ Pipeline 預處理缺口 (Gap Analysis)
1. **[缺口 1] 實時性斷裂**：`tpdep` 的 Azure Blob 存儲機制的同步頻率過低（> 5小時），需改接環境部 SensorThings API。
2. **[缺口 2] 靜動態不對等**：缺乏 `StationID` -> `Location` 的專門映射清洗步驟。
3. **[缺口 3] 異常值陷阱**：針對 `-99` 值的補值邏輯（Interpolation）尚未實作。
